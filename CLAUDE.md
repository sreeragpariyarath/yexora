# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Marketing/landing site for Yexora IT Solutions. Early stage: a single page (`app/page.tsx`) made of scroll sections over a fixed 3D scene (`ScrollFlow`), with the shared `Header` fixed on top. The page has a visually hidden `<h1>`. Nav links point to in-page anchors (`#about`, `#services`, `#works`, `#contact`), all of which exist.

**Content rules** (from the company's registration document and the owner): the company is "Yexora IT Solutions" (the registered name "Yexora IT Solutions Private Limited", `LEGAL_NAME` in `components/contact.ts`, appears only in the footer), located in "India" only (no city or state). Never show founder names. No game development and no training/internships for now. Services live in `components/flow/services.ts` (`SERVICES_CONTENT`; `SERVICES` = their titles, used by the contact dropdown); email (`contact@yexoraitsolutions.com`, real) and location live in `components/contact.ts` (shared by the menu and the contact section). No phone number anywhere: the owner doesn't want one.

## Commands

- `npm run dev` — dev server at http://localhost:3000
- `npm run build` — production build (also runs type checking). The site is a **static export** (`output: "export"` in `next.config.ts`): the build writes plain files to `out/`, and there is no server, so don't add API routes, server actions, middleware or anything request-time. `next/image` runs with `images.unoptimized`.
- `npm run lint` — ESLint (flat config, `eslint-config-next` core-web-vitals + typescript)

There is no test framework configured.

## Deployment and SEO

Deploy steps are in `README.md`.

- Icons and previews are file conventions in `app/`: `favicon.ico` (the owner's icon; don't add one to `public/`, it would conflict), `opengraph-image.png` / `twitter-image.png` (1200×630 link-preview card, currently the white Y logo mark (`logo-mark-loader.png`) centred on black; the owner will supply a final image) with `.alt.txt` files. The preview's title, description, site name, locale and Twitter card come from `metadata` in `app/layout.tsx`. They are static PNGs on purpose: a generated `opengraph-image.tsx` exports as an extensionless file, which static hosts serve without an image content type.

## Stack notes

- **Next.js 16 (App Router) + React 19.** These versions are newer than much training data; check `node_modules/next/dist/docs/` or the Next.js docs before relying on older APIs or conventions.
- **Tailwind CSS v4**, configured CSS-first in `app/globals.css` via `@import "tailwindcss"` and `@theme inline` — there is no `tailwind.config.js`. Add theme tokens there.
- Path alias `@/*` maps to the repo root (e.g. `@/components/Header`).
- `lucide-react` is used for the Contact section icons (`Mail`, `Phone`, `MapPin`, arrows); other icons are hand-built (`MenuIcon`) or inline SVGs.
- 3D uses `three` + `@react-three/fiber` v9 + `@react-three/drei` + `@react-three/postprocessing` (bloom).

## Styling conventions

- The site is dark-only: `app/layout.tsx` hard-codes the `dark` class on `<html>` and `bg-[#000000] text-zinc-100` on `<body>`. The light/dark CSS variables in `globals.css` are leftover scaffolding and are overridden by these classes.
- Fonts come from `next/font` (self-hosted, no Google Fonts stylesheet): Poppins (CSS var `--font-poppins-sans`, exposed as the `font-poppins` utility for body copy) and the display font **Bebas Neue** (`--font-bebas-neue`, `preload: false`, exposed as `font-bebas`; only the menu overlay uses it, and its components also set `fontFamily: "var(--font-bebas-neue), …"` inline). Keep each next/font var name different from its theme token to avoid a self-referencing var. Geist was removed: `body` sets Arial, so it was never rendered.
- Headline sizing uses viewport units (e.g. `lg:text-[4.4vw]`) so type scales with the screen.
- Accent colour is the `--color-accent` token in `globals.css` (`bg-accent`, `border-accent`, …).
- Animations are plain Tailwind transitions — no animation library or plugin is installed. In Tailwind v4, `translate-*`/`scale-*`/`rotate-*` set the individual CSS `translate`/`scale`/`rotate` properties, so custom transitions must list those (e.g. `transition-[translate,opacity]`), not `transform`.

## Menu

- `Header` (client component), fixed over the page: the white logo with wordmark on the left (`public/logo2-header.png`, a 278×168 copy of the owner's 3623×2192 logo — images are unoptimised in the static export, so the original was decoded in full; the original isn't kept in the repo, so export a new copy at about 168 px tall if the logo changes; `h-11 lg:h-14 w-auto`), nav links in the centre (a `lg:grid-cols-[1fr_auto_1fr]` grid keeps them truly centred; hidden below `lg`), and a "Get started" pill on the right (`GLASS_PILL` + `GlassPillParts` from `components/GlassPill.tsx`: a `liquid-glass` pill with a gradient arrow chip; it has `data-glass`, so the GPU lens refracts the fibres behind it). The desktop nav has no Contact link (the pill goes to `#contact`); the phone `MenuOverlay` still lists Contact. Below `lg`, a menu button beside the pill opens the full-screen `MenuOverlay`; there is no menu button on desktop. Nav items live in `NAV_ITEMS` / `MENU_ITEMS` constants in `Header.tsx`.
- Smooth scrolling is Lenis (`components/SmoothScroll.tsx`, `ReactLenis root`, wrapped around the app in `layout.tsx`). Same-page `#section` links glide slowly: `SmoothScroll` intercepts their clicks in the capture phase (before `next/link`, which would jump instantly), calls `lenis.scrollTo(target, { duration: 2, easing: easeInOutCubic })` and updates the hash. Home links use `#home` (the hero) rather than `/` so they glide too. Lock page scroll with `useLenis()?.stop()/start()`, not `body { overflow }`; nested scroll areas need `data-lenis-prevent`. Scrollbars are hidden site-wide in `globals.css` (`scrollbar-width: none` + `::-webkit-scrollbar`), so locking scroll causes no layout shift.
- `MenuOverlay` is always mounted and slides with `-translate-y-full` ↔ `translate-y-0`; its inner content wrapper travels a shorter distance (`translate-y-[60%]` → 0) on the same duration/ease, so both land together. Rows only fade in (no movement), so nothing shifts after the panel lands. While closed it is `inert` + `aria-hidden`. When open it stops Lenis, closes on Escape, and restores focus.
- Social links live in `components/socials.tsx` (`SOCIALS` + `<SocialLinks iconClassName>`), used by the menu footer and Contact; only LinkedIn now (the owner removed Instagram): `https://www.linkedin.com/company/yexora-it-solutions/`, opened in a new tab.
- `MenuLink` renders each label twice as per-letter spans (grey layer exits up, white layer enters from below) with an inline `transitionDelay` stagger, over an accent fill that scales up from the bottom border. Hover and `focus-visible` trigger the same effect. The link is `overflow-hidden` and the letter layers are `pointer-events-none` — rows are tightly stacked, so without this the moving letters spill into neighbouring rows and steal their hover.

## Loading screen

- `components/Loader.tsx` (rendered inside `<SmoothScroll>` in `app/layout.tsx`, so it is in the static HTML from the first paint): a black full-screen layer with `public/logo-mark-loader.png` (a white 256 px copy of the owner's logo mark; the original isn't kept in the repo) spinning one full turn clockwise (~1.4 s, eased), resting 1 s, and repeating (`.loader-mark` keyframes in `globals.css`; transform only, so it keeps turning on the compositor while the main thread is busy; it spins under reduced motion too, as the only loading indicator; the mark is `w-12 sm:w-14`). A `<noscript>` style hides it without JS. While it shows, Lenis is stopped.
- `lib/loading.ts` decides when it lifts: `markReady("scene")` (from FlowCanvas `Warmup`, or `SceneBoundary` if WebGL fails) and `markReady("fonts")` (`document.fonts.ready`), never before one spin (`MIN_MS`), and always by `MAX_MS` (15 s, so slow connections still get the scene first). Then it leaves in two steps: `leave()` fires first (`useLeaving()`; the logo fades and shrinks over 500 ms while still spinning, then the black layer fades over 700 ms after a 300 ms delay, and it unmounts at 1.1 s), and the page is told it's revealed `REVEAL_DELAY_MS` (350 ms) later — so the reveal's burst of work (re-renders, Lenis start, hero intro) can't stall the loader's fade, which made it look frozen. `useRevealed()` / `isRevealed()` / `onRevealed()` let the page wait for it.
- Work done behind it: the scene's `Warmup` runs `gl.compileAsync()` (the canvas doesn't render until it finishes, `flow.compiling`; rendering earlier compiles synchronously and froze the spinning logo), then waits for the logo's next rest (`whenLoaderResting()` in `lib/loading.ts`: the first real frames build the bloom/glass passes and stall the GPU process, which freezes compositor animations, so they run while the logo is still) and renders a few frames with `flow.warm = true` (the tail `Fibers` draw too), so every shader is compiled and every buffer uploaded before the first scroll — previously the tail fibres compiled the moment you scrolled to the beam, a visible hitch. The section photos are switched from lazy to eager so they're cached. Videos are **not** waited for (too big); see Works.
- Everything that animates in waits for the reveal: the hero fan's intro grow (`Driver` only advances `introTime` once revealed) and the `CopyBlock` / `GlassPanel` fade-ups (`shown = (seen || reduced) && revealed`).

## Scroll flow (3D)

- The page is real `<section>`s scrolling over one fixed WebGL canvas: `ScrollFlow` renders a `fixed inset-0` `FlowCanvas` plus `FlowSections` (`sections.tsx`). The sections are Hero, About, Principles, Services, Works intro, Works videos and Contact. Copy sections pin their text with a `sticky top-0 h-screen` child, so none of their ancestors may be `overflow-hidden`. Headings are Poppins medium in mixed case, rendered by the shared `CopyBlock` (eyebrow + title + body). It fades up once on first view; no scramble/glitch effects (the owner doesn't want them). Copy over the fibres uses `CopyBlock glass` (adds `data-glass` + `data-glass-shown`). Every glass box (`CopyBlock glass` and `GlassPanel`) has the same `#000000`/60 dark layer inside it, so bright fibres behind never wash out the text (the owner asked for it on all of them). About (`h-[160vh]`, shortened from 220vh because the long pinned stretch felt stuck) has its copy (three paragraphs on a wide 54vw card at `lg:pl-[30vw]`, a little right of centre, no inner tiles — the owner didn't like them; the third paragraph is hidden below `sm` so the card fits a phone) is drawn from the company's registered objects — no invented figures, clients or dates. `CopyBlock revealOnPin` (used by About) ties the card's appearance to scroll: a scroll listener sets `--reveal` 0→1 (eased) from when the section's top is 60% down the screen (no empty gap after the hero) until 20% past the top, driving opacity, scale (0.94→1) and a small rise, so it materialises as you scroll instead of popping in (the owner found the old instant reveal jarring). The liquid glass is rendered **on the GPU, like Apple's**: `glassLens.tsx` is a post-processing `Effect` (in its own `EffectGroup` pass after `<Bloom>`) that, inside each panel's rounded rect (SDF), refracts the scene along a curved bezel with a slight chromatic fringe, frosts the middle (so fibres don't make the text look tilted — the Zöllner illusion), adds a small milky tint (values are tiny because it's linear colour) and a pointer-reactive rim glint. `LiquidGlass` reads the panels' `getBoundingClientRect()` each frame (up to `MAX_PANELS` = 8 on screen) and fades each lens with `data-glass-shown`. It needs no `backdrop-filter`/SVG filters, so it works wherever the WebGL scene does, and pixels outside panels are untouched. While it runs, `<html>` has `webgl-glass` and `.liquid-glass` CSS only draws crisp details (rim, top highlight, shadow); without WebGL the `.liquid-glass` backdrop-filter version is the fallback, and `prefers-reduced-transparency` gets a solid panel. The owner wants clear "liquid display" glass, not frosted/smoked dark glass. Nested items use `.glass-tile`. Works sits on the plain background and doesn't use it. The lens only measures panels near the screen (an `IntersectionObserver`), in the frame loop's read phase.
- **Principles** (`Principles.tsx`, `id="principles"`, replaced the old Challenge card) and **Services** (`ServicesSection.tsx` — not `Services.tsx`, which would clash with `services.ts` on case-insensitive Windows — replaced the pinned "What we do" card) follow the owner's reference *layouts* but must match the site's design (the owner rejected a first version with giant bold lowercase titles and opaque dark rows): each opens with a `CopyBlock glass` header, and every card/row is a `GlassPanel` (liquid glass + GPU lens via `data-glass`, fade-up once in view, a `#000000`/60 dark layer inside). Principles is a bento grid; Services lists `SERVICES_CONTENT.items` as glass rows (number eyebrow, name, description, two thumbnails, each captioned with its title only — no sub-label). Rows don't stack/stick — glass is see-through, so stacked rows would show the text beneath. Photos go through `TintedImage` (the owner switched it to the images' normal colours: no greyscale or blue wash any more, just `contrast-110` and opacity 0.8, full on hover); Principles cards add a dark bottom gradient so their copy stays readable over the photo. Images are the owner's real ones, served as compressed 1280px WebP copies (about 100 KB each) in `public/images/web/` via `projectImage(name)` in `services.ts` (name = image name lower-cased with dashes). The ~2 MB original PNGs are not kept in the repo (the owner had them deleted); to add one, convert it with `sharp` (`resize({ width: 1280 }).webp({ quality: 80 })`) into `public/images/web/`. There are five services (the owner removed AI & Data and Cloud/DevOps & Security), and every Principles and Services image is real — no placeholders left. Both sections scroll normally (not pinned), so chapters 2 and 3 of the timeline span their content height.
- **Works**: the intro ("Selected works / Our Work in Motion") is the pinned glass card over the hourglass in `sections.tsx` (`id="works"`, the nav target; it replaced the old "What's next" card). The videos follow in `Works.tsx` (`id="work-videos"`), with no heading and no glass around them. Each video sits in a frame: a 1.5px lit gradient rim (matching the glass panels' edge), a deep drop shadow and a blue glow that brightens on the playing card, plus an inner edge highlight and soft top sheen over the video. Three muted video cards (from the left, right and bottom), with no captions (the owner doesn't want titles/categories shown; `title` is only the video's `aria-label`). The videos are served from Cloudflare R2 (bucket `yexora-media`, folder `videos/`) via the custom domain `media.yexoraitsolutions.com` — `MEDIA_BASE` in `Works.tsx`, with a `preconnect` in `app/layout.tsx`; they are not in the repo. Upload new videos to the bucket, not `public/`. Each card slides in via a scroll-set `--p` CSS var (measured in the frame loop's read phase, applied in the write phase), computed from the card's untransformed layout box (`list` rect top + `offsetTop`). The horizontal clip is on the full-width section, not the padded list, so cards enter from the screen edge — never `getBoundingClientRect()` on the card itself, which includes its own slide-in translate and made the cards shake. The same scroll listener picks **one active card**: the one nearest the viewport centre with at least 55% showing (`MIN_VISIBLE`), so it hands over when the next card is half in and the current one half out. The active card plays (while active it re-calls `play()` on `loadeddata`/`canplay`/`canplaythrough`/`stalled`/`pause`, since a refused or stalled first `play()` left the last card stuck on its first frame); the others pause and are dimmed by a dark overlay + desaturation. No sound (the owner asked for all videos muted). Videos start as `preload="metadata"`; an `IntersectionObserver` (rootMargin `200% 0px`) switches them all to `preload="auto"` about two screens before Works, and the first one also on idle after the loader, so the active card plays at once instead of buffering as you scroll onto it. The playing card's stronger shadow/glow is a separate layer whose opacity crossfades (animating a big blurred `box-shadow` repaints every frame), and the playing video has no CSS filter at all. A missing file shows a "Video coming soon" placeholder. While a card is active (`media.videoActive`, `lib/media.ts`), the canvas only redraws on scroll (`FrameBridge` skips frames when `scrollY` is unchanged): only faint specks are visible behind the videos, and redrawing bloom/glass every frame made the high-quality videos stutter.

There is no backend; submitting opens a `mailto:` listing the chosen services. The footer is one small, minimal centred line (10–11px, tracked, capitalised): `LEGAL_NAME`, "·", "© 2026 India" (no logo) (no nav links or Back to top, at the owner's request).
- **Chapter value `c`:** every `[data-chapter]` section is one chapter. `ScrollFlow` measures the sections' document tops (via `ResizeObserver`) into `layoutRef`. Each frame, `Driver` (a `useFrame` at priority -1) maps `window.scrollY` onto those tops, so `c = i` when section *i*'s top reaches the viewport top. Adding, removing or resizing a section shifts `c`, so retune `timeline.ts` when you do.
- **One frame clock, in phases:** `SmoothScroll` runs Lenis with `autoRaf={false}` and drives it from a single rAF loop that then calls `runFrame()` (`lib/frame.ts`). Subscribers register with `onFrame(cb, phase)` and run as all `"read"` (layout measurements), then all `"write"` (style changes), then `"render"` (the canvas, via `FrameBridge` → `advance`; the canvas is `frameloop="never"`). Works (`--p`, active card), CopyBlock (`--reveal`) and the glass lens (panel rects) measure in the read phase and apply in the write phase, so no rect read ever lands after a style write (each one forced a full layout mid-frame). Order per frame: Lenis scrolls → reads → writes → 3D + glass lens render, so nothing trails the page by a frame (two independent loops made the glass boxes shimmer/jump while scrolling). Don't add separate rAF loops or scroll listeners for scroll-synced visuals, and don't read layout in a write subscriber.
- **Smoothness rule:** Lenis already eases `scrollY` every frame, so `Driver` uses it as-is. Don't damp scroll again in the canvas (that caused lag). Scrolling never re-renders React. The Works cards' entrance is a CSS var (`--p`) set from the shared frame loop.
- **`timeline.ts`** holds the world layout (`FAN_A` node −14.5 / start −44, `FAN_B`, `WALL_A` −5 / `WALL_B` 11, `TAIL_X`; the hero camera starts at `camX` −4 and on About sits at 0.4, framing wall A on the left and fan B's node on the right, leaving the middle of the screen dark for the centred About card) and the keyframe `track`s in `c` for the camera, each fan, the tail and the particles. `track` interpolates with smoothstep between keys. `evaluate()` writes everything into the shared mutable `FlowState`, which scene components read in `useFrame`.
- **The chain:** the scene runs along +x and the camera pans right.
  - **Hero fan:** `Fan` with `FAN_A` grows in on load with no artificial delay: `LOAD_SECONDS` 2.2 with `easeOutCubic`, so it is visible from the first frames (the owner didn't want a delay). This is time-based (`load`), advanced by capped frame time (≤1/20 s per frame) so a shader-compile stall doesn't skip it. `ScrollFlow` starts downloading the `FlowCanvas` chunk at module load, before first render.
  - **Wall:** on scroll its strand ends land on a wall of glowing dots (`uWall`).
  - **Fan B:** its trunk starts back at fan A's node and runs along fan A's centre strand, so it reads as one fibre continuing through wall A. The trunk is kept to about one strand's worth of light, with a glowing tip while it grows, and brightens into its node. It then fans out evenly up and down (`FAN_B`, no bend), and hits wall B.
  - **Tail:** the tail `Fibers` escape the same way fan B does: a dim thread from fan B's node (`uThreadX`) through wall B to a node, then one thick lilac thread that widens only slightly. For the thread-like shapes (escape, beam), each strand's light scales with the bundle width (`escapeEnvelope`/`beamEnvelope` ÷ `BUNDLE`), so the tight bundle reads as one thread instead of stacking into a white bar. The draw-in front is feathered per strand. The hourglass shows only an evenly spaced subset of strands (`hourglassLine`, `LINES` angles, with a `boostOf` colour gain) so it reads as distinct lines crossing into a lattice. They then morph through the shapes in `fiberShader.ts` (escape → beam → hourglass → scatter), with `tailRotZ` swinging the beam. Scatter is invisible, so the scene fades out before the Works videos. The tubes interlude and the radial burst were removed at the user's request.
- **Shaders:** fan and fibre positions are computed in vertex shaders (`fanShader.ts`, `fiberShader.ts`) from `t` along the strand plus a per-strand seed. The fan's wall dots use the same GLSL chunk evaluated at `t = 1`. In the tail, scatter has alpha 0, and morphs out of it fade in at the target shape rather than flying in.
- **Loading and fallbacks:** the canvas is loaded with `next/dynamic({ ssr: false })`. It uses drei `PerformanceMonitor` to drop the dpr (1.5 → 1) on slow devices (mounted only 1.5 s after the reveal — judging the slow warm-up frames made it drop the dpr and resize everything right as the page appeared; `flipflops={3}`, then it settles on 1: each dpr change resizes the canvas and every post-processing buffer, a visible hitch if it keeps toggling), runs bloom at half resolution (threshold 0.25, radius 0.45, intensity 1 — kept tight on purpose: a lower threshold or wider radius fogs the navy background with a whitish haze, which the owner removed; particles are small specks only, no big bokeh blobs), and falls back to a static gradient (`SceneFallback.tsx`) when WebGL is missing: R3F throws if it can't create a context (its `fallback` prop only renders inside the `<canvas>`), so `ScrollFlow` wraps the canvas in an error boundary (`SceneBoundary`) that shows the gradient and releases the loader. Under reduced motion there is no intro grow, no pointer parallax and no copy fade-in.
- **Lint rule:** React Compiler lint (`react-hooks/immutability`) forbids mutating `useMemo` values or props. Declare three objects in JSX (`<shaderMaterial args={[params]} ref={…}>`) and mutate them through refs. Name ref props `…Ref` so the compiler treats them as refs.
